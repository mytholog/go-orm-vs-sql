# Go и базы данных: ORM vs SQL

Учебный репозиторий для вебинара. Один и тот же запрос к PostgreSQL реализован на GORM, pgx, sqlx и sqlc. Остальные примеры показывают N+1, динамические фильтры, конкурентное списание остатков и массовую вставку.

## Запуск

Нужны Go 1.25 или новее, Docker с Compose v2 и make. Используйте отдельную учебную базу: `make seed` заменяет её данные и создаёт 1 млн заказов и 1 млн позиций заказов.

```sh
make deps
make test
make up
make migrate
make seed
make test-integration
make demo-crud
```

Go-команды подключаются к учебной базе на `localhost:5432`. Для отдельного экземпляра PostgreSQL задайте `DATABASE_URL` для Go-команд и переопределите `PSQL` при вызове `make migrate seed plans`. PostgreSQL должен загружать `pg_stat_statements`.

Код sqlc хранится в репозитории, версии зависимостей закреплены в `go.mod` и `go.sum`. После изменений в `db/queries` или в схеме выполните `make generate`. Генерация запускает закреплённую версию sqlc и при необходимости скачивает её Go toolchain.

## Демонстрации

| Команда | Что наблюдать |
|---|---|
| `make demo-crud` | Четыре реализации чтения пользователя по ID |
| `make demo-n-plus-one` | На 100 пользователях 101 SELECT при загрузке в цикле и 2 с Preload |
| `make demo-zero-values` | Структура пропускает нулевой остаток, обновление через map сохраняет его |
| `make demo-select-star` | Время и размер значений на одном наборе строк с двумя проекциями |
| `make demo-filters` | Параметризованный запрос, построенный Squirrel |
| `make demo-transactions` | 100 запросов читают один остаток до записи; атомарный UPDATE списывает ровно 10 единиц |
| `make demo-bulk` | GORM CreateInBatches с RETURNING и pgx COPY на 100 тыс. строк |
| `make plans` | EXPLAIN ANALYZE до и после индекса и отчёт по выручке |

Массовая вставка использует временные таблицы. Замер охватывает вставку внутри транзакции без создания таблицы и коммита.

Суммы выражены в копейках. Примеры с остатками изменяют товар с ID 1. Повторно загрузите данные перед сравнением, если нужен исходный набор.

## Замеры

```sh
make bench
make profile
go tool pprof -http=:8080 cpu.out
make down
```

SQLX и GORM используют общий пул `database/sql`, pgx и sqlc — общий `pgxpool`. Каждый вариант выполняется последовательно с одинаковой проекцией. Сравнивайте `ns/op`, `B/op` и `allocs/op` по нескольким прогонам на одной машине.
